# Contributing to Verilay

Thank you for your interest in contributing. Verilay is built for the 99% of people who build apps with AI tools and deserve to understand what they built. Every contribution helps that mission.

## Ways to contribute

### Report a bug
Open an issue with:
- What you did
- What you expected to happen
- What actually happened
- The repo URL or platform you were analysing (if shareable)

### Suggest a feature
Open an issue tagged `enhancement`. Describe:
- The problem you're trying to solve
- Who would benefit
- What you'd expect Verilay to do

### Submit a pull request
1. Fork the repo
2. Create a branch: `git checkout -b feature/your-feature-name`
3. Make your changes
4. Test locally: `python app.py` then run an analysis
5. Commit: `git commit -m "feat: description of what you added"`
6. Push and open a PR

## What we're looking for

**High priority:**
- Improving the Claude analysis prompt for better layer classification
- Adding support for more platforms (Bolt, v0, Windsurf)
- Better handling of monorepos and complex file structures
- Improving the learner mode explanations
- Adding more quiz questions per layer

**Good first issues:**
- Improving error messages when GitHub rate limits hit
- Adding a loading progress indicator
- Better mobile responsive layout
- Dark mode support

## Code style

- Python: follow PEP 8, keep functions focused and named clearly
- HTML/JS: keep it in the single app.py file for now — simplicity is the priority
- Comments: explain *why*, not *what*

## Questions?

Open an issue tagged `question`. No question is too basic — if you're confused, others probably are too.
